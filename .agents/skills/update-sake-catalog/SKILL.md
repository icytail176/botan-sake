# 更新酒款图鉴

沿用当前Astro项目、数据模型和现有脚本，完成可复核的内容更新。默认只在本地工作。
本文链接相对于Skill目录；命令和数据路径均相对于项目根目录。

## 1. 检查工作状态

读取根目录 [AGENTS.md](../../../AGENTS.md)、[README](../../../README.md)，检查 `git status`、分支和diff，保留已有未提交修改。按任务读取卷目录、`data/manual.json`及相关研究记录，不重做已验证研究。

素材/格式/关联读 [CONTENT_GUIDE](../../../docs/CONTENT_GUIDE.md)；规格或文章读 [RESEARCH_GUIDE](../../../docs/RESEARCH_GUIDE.md)；构建/发布读 [DEPLOYMENT](../../../docs/DEPLOYMENT.md)。不必为单一链接修改加载全部历史。

## 2. 定位目标

用卷数、卷内编号找到登场ID（如`v01-004`），再检查`appearances.ID.productId`定位商品。商品ID永久保留；相同编号可跨卷重复，不能仅凭相似名称合并产品。已有人工覆盖优先于info文本。

## 3. 检查素材

匹配 `第N巻/products/`、`scenes/` 的数字编号及截图后缀，保留原图字节、原始文件名和其他酒款资源。多图、冲突和内容去重由现有导入脚本处理，不能随意选择冲突文件。

新增卷只在有真实名称/图片/截图等任务资料时创建；资料不足先报告缺项，不为测试或凑卷数创建正式记录。跨卷重复出现须保留新登场ID，并明确指定旧商品productId；新登场不继承confirmed。

## 4. 核实资料

涉及数值、原料、工艺、简介、风味或背景时，优先读取官方及权威的准确商品资料，必要时采用有明确产品对应和范围的专业酒商正文。保存具体URL、查询日期和适用年份/批次/容量。不能用搜索摘要或无法访问的页面冒充已读证据。

区分年份、NV、Reserva、限定版与仕込号；精米歩合法定上限不是某款的实际值。无法核实留null/不添加，原因记specificationGaps和研究报告；冲突不任选一个数值。风味注明来源归属，品牌背景不当作商品原料产地或本站试饮。

## 5. 合并维护数据

- 基础名称、商品URL在对应卷 `info.txt`；存在 `products.ID.name/url` 人工覆盖时同步修改，防止重新导入恢复旧信息。
- 人工覆盖、分类/categorySource、规格、介绍、风味、背景及来源写 `data/manual.json` 的products；登场确认、备注、内部出处和跨卷productId写appearances。
- 规格用label/value/sourceIds；规格与文章的sourceIds引用同商品specificationSources中唯一ID，填写checkedAt和必要versionNote。单行note限定版本，不用猜测值或占位文案填满表格。
- 仅合并任务涉及条目，保留其他字段。不得直接改catalog.json/imported.json作为人工入口，不重复加入已有规格或文章。
- 不自动确认新增记录，不擅自更改现有confirmed。只有用户明确核对作品识别时才设置相应登场状态；商品官网本身不证明作品对应。

## 6. 验证

内容更新至少在根目录运行 `npm run verify`，它调用现有导入、测试、类型检查、构建和资源验证，不另造导入流程。检查导入报告、人工数据重新导入仍保留、图像哈希/编号关联、路由和来源引用；失败先修正，不能关闭测试。

重要网页可见变化在环境可用时启动构建预览并 `npm run test:browser`，检查目标详情、搜索/筛选、导航、Lightbox和375/390/768/1440px。若浏览器不可用如实区分未执行项目。已有回归基准保护原10款；有意修改基准先核对新证据及用户授权，不能只为通过测试改写。

Skill维护验证用 `node --test tests/maintenance.test.mjs`（临时目录A/B/C场景及文档链接检查）；不向正式图鉴写测试数据。

## 7. 汇报更新

说明酒款/卷/永久ID、实际修改、具体来源和版本、未核实项、确认状态、图片关联及测试结果；研究事实与推断区分。无规格就不显示空行，无来源的文章不添加。

## 8. 发布边界

默认结束于本地可检查成果，报告尚未提交/推送。仅当用户明确授权相应提交、推送及发布动作时，按DEPLOYMENT执行正常提交、推送、等待Actions并实际线上验收；已有授权覆盖本次变更时继续，不再重复询问。授权只提交不能扩展为发布。

未授权时不调用远程写入或workflow_dispatch，不force push，不修改/删除旧image-host仓库。不通过破坏性Git操作清除未知工作。网络或部署失败报告实际状态，不宣称成功。
